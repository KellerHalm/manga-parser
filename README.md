## Быстрый старт


Формат любой команды: `python main.py <источник> <команда> [аргументы]`.

## Команды

| Команда     | Что делает                                            |
|-------------|-------------------------------------------------------|
| `search`    | серверный поиск по названию (1 запрос, ~0.3 с)         |
| `catalog`   | одна страница каталога (`--page`, `--sort`, `--count`) |
| `latest`    | лента новинок (remanga)                                |
| `details`   | карточка тайтла (slug подставляется автоматически)     |
| `chapters`  | список глав                                            |
| `dump`      | полный обход каталога в JSON + CSV + JSONL             |
| `enrich`    | дозагрузить полные карточки: описание, жанры, авторы   |
| `build`     | собрать JSON/CSV из чекпоинта, без единого запроса     |
| `index`     | построить офлайн-индекс из выгрузок                   |
| `offline`   | поиск по офлайн-индексу (мгновенно, без сети)         |
| `merge`     | склеить выгрузки разных источников в один файл        |

Примеры:

```bash
python main.py remanga dump --csv --delay 0.3             # весь каталог (~30k)
python main.py remanga dump --max-pages 5                # первые 5 страниц
python main.py remanga details naruto                    # dir подставится сам
python main.py remanga enrich --limit 200 --csv          # дозагрузить карточки
python main.py inkstory enrich --limit 0 --csv           # весь каталог, без ограничения

python main.py index --catalog data/remanga_catalog.json --reset
python main.py offline "берсерк"
python main.py merge data/remanga_catalog.json data/inkstory_catalog.json
```

## Полные данные тайтла: `dump` и `enrich`

Каталог и карточка отдают разный объём. `dump` быстрый, но это срез: название,
обложка, рейтинг, статус. Полная карточка добавляет описание, жанры, авторов,
издателей — но стоит одного запроса на тайтл.

Поэтому полнота получается двумя шагами:

```bash
python main.py remanga dump                        # 1: быстрый обход каталога
python main.py remanga enrich --limit 0 --csv      # 2: дозагрузка карточек
```

`enrich` одинаков для всех источников: достаточно, чтобы источник умел
`details()` — отдельного кода под каждый сайт нет.

Обогащённая запись помечается полем `details_at`, поэтому повторный запуск
**продолжает** с места остановки, а не начинает по новой; прерывание не теряет
собранное, а `--refresh` обогащает заново уже помеченные записи.

Про MangaLIB стоит понимать: это не недосмотр парсера. Публичный API
(`/api/manga/{slug}`) возвращает **подмножество** полей каталога — описаний,
жанров и авторов в нём нет вовсе, сайт собирает их на клиенте. Проверено по
`api2`/`api.cdnlibs.org` и по бандлу фронтенда, где других адресов нет. Поэтому
источник помечен `enrichable = False`, чтобы `enrich` не делал тысячи запросов
впустую.

### Устойчивость к обрывам

`dump` пишет прогресс в `<имя>_catalog.jsonl` по мере обхода. Прерывание
(Ctrl+C, краш, 429) не теряет собранное — повторный запуск продолжит с
чекпоинта. `--fresh` начинает с нуля. При 429 пауза автоматически
удваивается до 60 с.

`enrich` работает так же: прогресс дописывается в тот же чекпоинт, а
обогащённые записи помечаются полем `details_at`, поэтому повторный запуск
берёт только то, что ещё не загружено.

### BuZuManga: особенности сайта

Сайт — SPA, в HTML данных нет, всё отдаёт JSON API:

| Что            | Запрос                                          |
|----------------|-------------------------------------------------|
| каталог        | `/api/manga?limit=&offset=&sort=`               |
| поиск          | `/api/manga/search?q=` (сервер даёт максимум 10) |
| карточка       | `/api/manga/{id}`                               |
| главы          | `/api/manga/{id}/chapters`                      |
| страницы главы | `/api/manga/{id}/chapters/{номер}/pages`        |
| размер базы    | `/api/manga/stats`                              |

Что стоит знать:

- пагинация каталога — через `offset`, а не `page` (100 записей на страницу);
- `id` тайтла и есть ключ (`python main.py buzumanga details 2634`); slug в
  API нет, для URL он собирается транслитерацией (`slug.py`);
- пути картинок приходят относительными и раздаются с отдельного CDN —
  в выгрузку пишутся как есть, абсолютный URL даёт `image_url()`;
- сайт рвёт keep-alive после каждого ответа, поэтому клиент шлёт
  `Connection: close`: без этого каждый второй запрос падает с
  `ConnectionError` и обход вязнет на ретраях и 429;
- `robots.txt` запрещает обход `/api/`, поэтому каталог выгружается для
  личных нужд, с `--delay` и без `--fresh`-циклов по кругу. Примерно после
  12 000 быстрых запросов сайт начинает отдавать 429 на несколько минут —
  обход сам откатывается на паузу до 60 с и продолжает с чекпоинта.

### Com-X: особенности сайта

com-x.life (DLE) закрыт антибот-защитой: корень, категории и карточки отдают
404 с редиректом на `/_c?t=...`, где браузер обязан пройти proof-of-work,
снять отпечаток окружения (WebGL/canvas/таймзона) и детект автоматизации
(`navigator.webdriver`, CDP). Такой обход парсер писать нельзя, поэтому
источник берёт только то, что сайт публикует открытым — свой sitemap:

| Что       | Откуда                        |
|-----------|-------------------------------|
| каталог   | `/sitemap.xml` -> `news_pages*.xml` |
| всего     | 28 292 адреса, 3 сетевых запроса |

Из sitemap доступны только `id`, `url`, название из slug и `lastmod`. Поэтому
`chapters()` возвращает пусто, а `search()` ищет локально по скачанным
sitemap (серверный `/search/` запрещён в `robots.txt` и закрыт челленджем).

```bash
python main.py comx search "schenok"
python main.py comx details 34100
```

### Desu.Me: особенности сайта

desu.uno (XenForo) отдаёт всё нужное в разметке, но `robots.txt` закрывает три
вещи, которые обычно и делают каталог: пагинацию `/manga/?page=N`, поиск
`/manga/search/*` и страницы глав `/manga/*/vol*/ch*/`. Из открытого остаются
свой sitemap и карточка тайтла — на этом источник и построен:

| Что             | Откуда                                    |
|-----------------|-------------------------------------------|
| каталог         | `/sitemap.php` — 7 056 карточек, 1 запрос |
| карточка        | `/manga/<slug>.<id>/` — открыта            |
| список глав     | целиком лежит на карточке, без пагинации   |

Поэтому `catalog()` — это срез уже скачанного sitemap (весь каталог стоит один
сетевой запрос), а `search()` ищет локально: в sitemap лежит название из slug,
то есть искать нужно по оригинальному названию, а не по русскому. `details()`
и `chapters()` идут на карточку и отдают всё остальное — описание, жанры,
авторов, переводчиков, рейтинг, просмотры и полный список глав:

```bash
python main.py desu dump --csv                  # весь каталог, 1 запрос
python main.py desu search "one piece"          # по оригинальному названию
python main.py desu details 12                  # id подставится сам
python main.py desu chapters 12
python main.py desu enrich --limit 0 --csv      # полные карточки всего каталога
```

или 401 — это норма, а не сбой: такие записи `enrich` пропускает и идёт дальше

только на 404/422 — иначе сырое исключение обрывало бы весь обход).

### SelfManga: особенности сайта

1.selfmanga.live — русский сайт авторской манги (личные тайтлы, додзинси,
вебтуны). Публичного JSON API с данными **нет**: в оболочке объявлен
`SERVER_API_URL = '/api'`, но этот префикс отдаёт 404, а весь контент приходит
в HTML — сайт рендерится на сервере целиком. Поэтому используются страницы:

| Что            | Запрос                                          |
|----------------|-------------------------------------------------|
| каталог        | `/list?sortType=<сортировка>&offset=N`, 50/стр. |
| размер базы    | «Всего N» в заголовке `/list` (3410 тайтлов)   |
| поиск          | `/search/advancedResults?q=<запрос>&offset=N`   |
| подсказки      | `/search/suggestion?query=` — единственный JSON |
| карточка       | `/<slug>`                                       |
| главы          | разметка `/<slug>`, пагинации нет               |
| страницы главы | `/<slug>/volV/N` -> `rm_h.readerInit(...)`       |

Что стоит знать:

- тайтл адресуется транслитерированным slug (`/djodjo__vpered_legenda_`), а не
  числовым id; id есть только в разметке (`div.tile.el_9117`, `data-id` списка
  глав) и он же используется для дедупликации выгрузки;
- **каталог отдаёт больше, чем видно без наведения мыши**: в каждую плитку
  вложен попап с оригинальным названием, полным списком жанров, описанием и
  автором. `dump` поэтому уже даёт описание и жанры, а `enrich` добавляет то,
  чего в плитке нет в принципе: статус выпуска, томов, персон с ролями, оценки
  по категориям (сюжет/персонажи/мир), год, тип, возрастной рейтинг, фоны и
  статистику читателей;
- главы лежат в разметке карточки целиком (у тайтла на 300+ глав страница всё
  равно одна), но номер главы брать нужно из URL, а не из `data-num`: там
  лежит внутренний счётчик, 20-я глава тома 5 помечена как `data-num="200"`;
- `robots.txt` требует `Crawl-delay: 1` и `Request-rate: 1/1`, поэтому пауза по
  умолчанию здесь 1 с, а `/internal/*` из `robots.txt` не обходится вовсе;
- сортировка по названию на сайте сломана: `/list?sortType=name` отдаёт первую
  страницу, а вторая уже пустая. Обход по ней невозможен, поэтому для полного
  каталога используются `popularity` (по умолчанию), `created`, `updated`,
  `rating`;
- **страницы глав (`chapter_pages`) есть не у всех глав.** Список картинок лежит
  в разметке ридера (`rm_h.readerInit`), но сайт отдаёт его не всегда: главы
  18+ и главы, которые ещё не опубликованы, гостю открываются как карточка
  тайтла — без вызова `readerInit` и без картинок. В этом случае метод честно
  возвращает пустой список; обойти это без учётной записи нельзя. Список глав
  при этом отдаётся полностью и всегда.

Правила, которые держат архитектуру чистой:

- **core** не знает ни про один сайт и не импортирует `requests`-логику выше себя.
- **application** работает только через порты `core.ports.Source`; названий

- **sources** могут зависеть от `core`, но не друг от друга и не от

- **cli** только собирает аргументы и вызывает сценарии; бизнес-логики в нём нет.

### Как добавить источник

1. Создать `src/mangaparser/sources/<name>/client.py` с классом клиента:

```python
from ...core.http import Http, Throttle, build_session
from ...core.models import Item

class MyClient:
    name = "mysite"
    item_class = MyBook        # dataclass, наследующий Item
    dedupe_key = "id"          # поле дедупликации в выгрузке
    key_hint = "slug"          # что нужно для details()/chapters()
    enrichable = True          # False, если details() не даёт больше каталога

    def catalog(self, page: int = 1, **kw) -> list[MyBook]: ...
    def search(self, query: str, page: int = 1, **kw) -> list[MyBook]: ...
    def details(self, key: str, **kw) -> MyBook: ...   # карточка: описание, жанры, авторы
    def chapters(self, key: str, **kw) -> list[dict]: ...
    def iter_catalog(self, *, delay, max_pages=None, checkpoint=None, on_page=None, **kw): ...
```

2. Добавить `build()` и `describe()` в модуль.
3. Вписать одну строку в `sources/registry.py`.

CLI, `application` и тесты при этом не меняются: команды уже есть.

## Выгрузки

`dump` создаёт три файла с одинаковыми данными:

- `<source>_catalog.json` — основной формат;
- `<source>_catalog.csv` — для Excel (UTF-8 BOM, колонки — объединение всех полей);
- `<source>_catalog.jsonl` — чекпоинт по ходу обхода, из него же строится
  офлайн-индекс.

Во всех записях есть колонка `source`, а `title` приведено к общему виду —
поэтому каталоги разных сайтов можно склеивать в один датасет.
