# manga-parser

Парсеры каталогов манги: **MangaLIB**, **ReManga**, **InkStory**, **BuZuManga**,
**Com-X**, **Desu.Me**, **SelfManga**. Один вход, одинаковые команды для всех источников,
чистая архитектура — новый сайт подключается без правок логики и CLI.

Поверх парсеров — **графическое приложение на Flet**: Android, iOS и десктоп,
читатель манги с библиотекой, поиском по всем площадкам сразу и офлайн-чтением.
Подробности — в разделе [Приложение](#приложение-manga-gui).

## Быстрый старт

```bash
pip install -r requirements.txt

python main.py                                    # список источников и команд
python main.py sources                            # только источники
python main.py mangalib search "берсерк"
python main.py remanga  catalog --page 1
python main.py buzumanga dump --csv --max-pages 10
python main.py comx      search "schenok"
python main.py selfmanga search "берсерк"
python main.py inkstory dump --csv --max-pages 10
python main.py desu      search "one piece"
python main.py all      search "наруто"           # по всем источникам сразу
python main.py gui                                  # графическое приложение
```

Формат любой команды: `python main.py <источник> <команда> [аргументы]`.

## Команды

| Команда     | Что делает                                            |
|-------------|-------------------------------------------------------|
| `search`    | серверный поиск по названию (1 запрос, ~0.3 с)         |
| `catalog`   | одна страница каталога (`--page`, `--sort`, `--count`) |
| `latest`    | лента новинок (remanga)                                |
| `details`   | карточка тайтла (slug подставляется автоматически)     |
| `chapters`  | список глав (`--pages` — ещё и число страниц)         |
| `pages`     | адреса картинок главы (страниц)                        |
| `dump`      | полный обход каталога в JSON + CSV + JSONL             |
| `enrich`    | дозагрузить полные карточки: описание, жанры, авторы   |
| `build`     | собрать JSON/CSV из чекпоинта, без единого запроса     |
| `index`     | построить офлайн-индекс из выгрузок                   |
| `offline`   | поиск по офлайн-индексу (мгновенно, без сети)         |
| `merge`     | склеить выгрузки разных источников в один файл        |

Примеры:

```bash
python main.py remanga dump --csv --delay 0.3             # весь каталог (~30k)
python main.py remanga dump --max-pages 5                # первые 5 страниц
python main.py remanga details naruto                    # dir подставится сам
python main.py remanga enrich --limit 200 --csv          # дозагрузить карточки
python main.py inkstory enrich --limit 0 --csv           # весь каталог, без ограничения
python main.py selfmanga enrich --limit 0 --delay 1 --csv  # весь каталог, 1 req/сек
python main.py index --catalog data/remanga_catalog.json --reset
python main.py offline "берсерк"
python main.py merge data/remanga_catalog.json data/inkstory_catalog.json
```

## Страницы глав

У каждого источника есть `chapter_pages(key, chapter)` — адреса картинок главы.
Сигнатура общая, поэтому прикладной слой и CLI не знают, что у MangaLIB глава
адресуется по `id`, а у SelfManga — по адресу страницы: `chapter` берётся из
`chapters()` и уже знает всё нужное.

```bash
python main.py inkstory pages one-piece --chapter 0        # первая глава
python main.py remanga  pages berserk_of_gluttony_         # страницы бесплатно
python main.py buzumanga pages 2634 --limit 5              # первые пять адресов
python main.py desu     pages 12 --url https://desu.uno/manga/one-piece.12/vol1/ch1/rus
python main.py inkstory chapters one-piece --pages          # число страниц у каждой главы
```

| Источник     | как достаются страницы                                | ограничения |
|--------------|-------------------------------------------------------|-------------|
| **ReManga**  | список картинок уже лежит в главе (`content`)          | сети нет, работает мгновенно |
| **MangaLIB** | `/api/manga/{slug}/chapter/{id}`                       | адрес главы — её `id` |
| **BuZuManga**| `/api/manga/{id}/chapters/{номер}/pages`               | относительные пути дописываются CDN-префиксом |
| **SelfManga**| ридер `/<slug>/volV/N` -> `rm_h.readerInit(...)`        | главы 18+ и неопубликованные гостю отдаются без картинок |
| **InkStory** | ридер `/content/<slug>/<uuid>` -> SSR-payload `pages`   | сервер отдаёт только первую страницу списка глав (41 шт.) |
| **Desu.Me**  | ридер -> `/api/manga/{id}/chapters/{id}`                | **только первая глава тома** (`volN/ch1/rus`) — остальные закрыты `robots.txt` |
| **Com-X**    | —                                                      | антибот-челлендж: поднимает ошибку, а не возвращает пустоту |

Колонка со страницами в `chapters` заполняется тем, что глава знает о себе
(`page_count` у BuZuManga, список страниц у ReManga); остальным нужно по
запросу на главу — это и делает флаг `--pages`.

## Полные данные тайтла: `dump` и `enrich`

Каталог и карточка отдают разный объём. `dump` быстрый, но это срез: название,
обложка, рейтинг, статус. Полная карточка добавляет описание, жанры, авторов,
издателей — но стоит одного запроса на тайтл.

Поэтому полнота получается двумя шагами:

```bash
python main.py remanga dump                        # 1: быстрый обход каталога
python main.py remanga enrich --limit 0 --csv      # 2: дозагрузка карточек
```

`enrich` одинаков для всех источников: достаточно, чтобы источник умел
`details()` — отдельного кода под каждый сайт нет.

Обогащённая запись помечается полем `details_at`, поэтому повторный запуск
**продолжает** с места остановки, а не начинает по новой; прерывание не теряет
собранное, а `--refresh` обогащает заново уже помеченные записи.

Что реально удаётся вытащить с каждого сайта:

| Источник     | Описание | Жанры                    | Рейтинг              | Авторы / издатели                      | Ещё                                                    |
|--------------|----------|--------------------------|----------------------|----------------------------------------|--------------------------------------------------------|
| **ReManga**  | да       | да + рубрики `categories` | да                  | да (`authors` / `publishers`)          | возрастное ограничение, заметка, обои, наличие аниме     |
| **InkStory** | да       | да                       | да + число голосов   | автор, художник, издатели, переводчики, журнал | страна, статус, год, главы, просмотры, лайки, другие названия |
| **BuZuManga** | да      | да (`tags`)              | да + число голосов   | —                                      | закладки, дата оригинала, типы, возрастной рейтинг     |
| **Desu.Me**  | да       | да + рубрики `tags`      | да + число голосов   | авторы, переводчики                    | год, статус оригинала и перевода, просмотры, направление чтения, другие названия |
| **SelfManga**| да       | да + метки (`tags`)      | да + 3 оценки по категориям | автор, художник, сценарист (`people`) | статус выпуска, томов, частота выхода, год, тип, возрастной рейтинг, фоны, статистика читателей |
| **MangaLIB** | —        | —                        | только из каталога   | —                                      | сайт не отдаёт это в API                                |
| **Com-X**    | —        | —                        | —                    | —                                      | только sitemap: id, url, название, `lastmod`            |

Про MangaLIB стоит понимать: это не недосмотр парсера. Публичный API
(`/api/manga/{slug}`) возвращает **подмножество** полей каталога — описаний,
жанров и авторов в нём нет вовсе, сайт собирает их на клиенте. Проверено по
`api2`/`api.cdnlibs.org` и по бандлу фронтенда, где других адресов нет. Поэтому
источник помечен `enrichable = False`, чтобы `enrich` не делал тысячи запросов
впустую.

### InkStory: особенности сайта

Каталог и карточка рендерятся на сервере, а главы живут на отдельной вкладке
`/content/<slug>/chapters`, и адресуются **uuid**, а не номером:

| Что            | Откуда                                                     |
|----------------|------------------------------------------------------------|
| главы          | `/content/<slug>/chapters`, в `aria-label` — «Глава N: …» |
| страницы главы | `/content/<slug>/<uuid>` -> SSR-payload `initialChapter`   |

Два ограничения сайта, из-за которых возможности скромнее, чем кажется:

- **список глав неполный.** Сервер отдаёт только первую виртуальную страницу —
  41 глава из 1217 у One Piece. Остальное догружает клиент через `/api`, а он
  закрыт в `robots.txt`, поэтому `?page=N` возвращает ту же первую страницу и
  обойти запрет, не нарушив его, нельзя;
- **страницы главы лежат в payload ридера**, а не в отдельном API. В том же
  payload лежат данные соседних глав, поэтому берутся только страницы той главы,
  чей `uuid` указан в `initialChapter`.

### Устойчивость к обрывам

`dump` пишет прогресс в `<имя>_catalog.jsonl` по мере обхода. Прерывание
(Ctrl+C, краш, 429) не теряет собранное — повторный запуск продолжит с
чекпоинта. `--fresh` начинает с нуля. При 429 пауза автоматически
удваивается до 60 с.

`enrich` работает так же: прогресс дописывается в тот же чекпоинт, а
обогащённые записи помечаются полем `details_at`, поэтому повторный запуск
берёт только то, что ещё не загружено.

### BuZuManga: особенности сайта

Сайт — SPA, в HTML данных нет, всё отдаёт JSON API:

| Что            | Запрос                                          |
|----------------|-------------------------------------------------|
| каталог        | `/api/manga?limit=&offset=&sort=`               |
| поиск          | `/api/manga/search?q=` (сервер даёт максимум 10) |
| карточка       | `/api/manga/{id}`                               |
| главы          | `/api/manga/{id}/chapters`                      |
| страницы главы | `/api/manga/{id}/chapters/{номер}/pages`        |
| размер базы    | `/api/manga/stats`                              |

Что стоит знать:

- пагинация каталога — через `offset`, а не `page` (100 записей на страницу);
- `id` тайтла и есть ключ (`python main.py buzumanga details 2634`); slug в
  API нет, для URL он собирается транслитерацией (`slug.py`);
- пути картинок приходят относительными и раздаются с отдельного CDN —
  в выгрузку пишутся как есть, абсолютный URL даёт `image_url()`;
- сайт рвёт keep-alive после каждого ответа, поэтому клиент шлёт
  `Connection: close`: без этого каждый второй запрос падает с
  `ConnectionError` и обход вязнет на ретраях и 429;
- `robots.txt` запрещает обход `/api/`, поэтому каталог выгружается для
  личных нужд, с `--delay` и без `--fresh`-циклов по кругу. Примерно после
  12 000 быстрых запросов сайт начинает отдавать 429 на несколько минут —
  обход сам откатывается на паузу до 60 с и продолжает с чекпоинта.

### Com-X: особенности сайта

com-x.life (DLE) закрыт антибот-защитой: корень, категории и карточки отдают
404 с редиректом на `/_c?t=...`, где браузер обязан пройти proof-of-work,
снять отпечаток окружения (WebGL/canvas/таймзона) и детект автоматизации
(`navigator.webdriver`, CDP). Такой обход парсер писать нельзя, поэтому
источник берёт только то, что сайт публикует открытым — свой sitemap:

| Что       | Откуда                        |
|-----------|-------------------------------|
| каталог   | `/sitemap.xml` -> `news_pages*.xml` |
| всего     | 28 292 адреса, 3 сетевых запроса |

Из sitemap доступны только `id`, `url`, название из slug и `lastmod`. Поэтому
`chapters()` возвращает пусто, а `chapter_pages()` поднимает ошибку с
объяснением: пустой список выглядел бы как «глава без картинок», а на деле
список глав лежит за антибот-челленджем и недоступен без браузера с
JavaScript. `search()` ищет локально по скачанным sitemap (серверный
`/search/` запрещён в `robots.txt` и закрыт челленджем). Весь обход — 3 запроса
и ~3 с:

```bash
python main.py comx dump --csv
python main.py comx search "schenok"
python main.py comx details 34100
```

### Desu.Me: особенности сайта

desu.uno (XenForo) отдаёт всё нужное в разметке, но `robots.txt` закрывает три
вещи, которые обычно и делают каталог: пагинацию `/manga/?page=N`, поиск
`/manga/search/*` и страницы глав `/manga/*/vol*/ch*/`. Из открытого остаются
свой sitemap и карточка тайтла — на этом источник и построен:

| Что             | Откуда                                    |
|-----------------|-------------------------------------------|
| каталог         | `/sitemap.php` — 7 056 карточек, 1 запрос |
| карточка        | `/manga/<slug>.<id>/` — открыта            |
| список глав     | целиком лежит на карточке, без пагинации   |
| страницы главы  | `/manga/<slug>.<id>/volN/ch1/rus` — единственная разрешённая |

Поэтому `catalog()` — это срез уже скачанного sitemap (весь каталог стоит один
сетевой запрос), а `search()` ищет локально: в sitemap лежит название из slug,
то есть искать нужно по оригинальному названию, а не по русскому. `details()`
и `chapters()` идут на карточку и отдают всё остальное — описание, жанры,
авторов, переводчиков, рейтинг, просмотры и полный список глав:

```bash
python main.py desu dump --csv                  # весь каталог, 1 запрос
python main.py desu search "one piece"          # по оригинальному названию
python main.py desu details 12                  # id подставится сам
python main.py desu chapters 12
python main.py desu enrich --limit 0 --csv      # полные карточки всего каталога
python main.py desu pages 12 --url https://desu.uno/manga/one-piece.12/vol1/ch1/rus
```

Страницы глав у desu.uno закрыты `robots.txt` (`Disallow: /manga/*/vol*/ch*/`)
с единственным исключением — `Allow: /manga/*/vol*/ch1/rus`. Поэтому
`chapter_pages()` работает только для первой главы тома, а для любой другой
поднимает ошибку вместо того, чтобы обходить запрет. Сам список картинок лежит
не в разметке, а в ответе `/api/manga/{id}/chapters/{id}` — эндпоинт в
`robots.txt` не закрыт.

Часть тайтлов в sitemap отдаёт 451 («закрыто по требованию правообладателя»)
или 401 — это норма, а не сбой: такие записи `enrich` пропускает и идёт дальше
(ради этого `Http` поднимает `SourceError` на любой код ответа >= 400, а не
только на 404/422 — иначе сырое исключение обрывало бы весь обход).

### SelfManga: особенности сайта

1.selfmanga.live — русский сайт авторской манги (личные тайтлы, додзинси,
вебтуны). Публичного JSON API с данными **нет**: в оболочке объявлен
`SERVER_API_URL = '/api'`, но этот префикс отдаёт 404, а весь контент приходит
в HTML — сайт рендерится на сервере целиком. Поэтому используются страницы:

| Что            | Запрос                                          |
|----------------|-------------------------------------------------|
| каталог        | `/list?sortType=<сортировка>&offset=N`, 50/стр. |
| размер базы    | «Всего N» в заголовке `/list` (3410 тайтлов)   |
| поиск          | `/search/advancedResults?q=<запрос>&offset=N`   |
| подсказки      | `/search/suggestion?query=` — единственный JSON |
| карточка       | `/<slug>`                                       |
| главы          | разметка `/<slug>`, пагинации нет               |
| страницы главы | `/<slug>/volV/N` -> `rm_h.readerInit(...)`       |

Что стоит знать:

- тайтл адресуется транслитерированным slug (`/djodjo__vpered_legenda_`), а не
  числовым id; id есть только в разметке (`div.tile.el_9117`, `data-id` списка
  глав) и он же используется для дедупликации выгрузки;
- **каталог отдаёт больше, чем видно без наведения мыши**: в каждую плитку
  вложен попап с оригинальным названием, полным списком жанров, описанием и
  автором. `dump` поэтому уже даёт описание и жанры, а `enrich` добавляет то,
  чего в плитке нет в принципе: статус выпуска, томов, персон с ролями, оценки
  по категориям (сюжет/персонажи/мир), год, тип, возрастной рейтинг, фоны и
  статистику читателей;
- главы лежат в разметке карточки целиком (у тайтла на 300+ глав страница всё
  равно одна), но номер главы брать нужно из URL, а не из `data-num`: там
  лежит внутренний счётчик, 20-я глава тома 5 помечена как `data-num="200"`;
- `robots.txt` требует `Crawl-delay: 1` и `Request-rate: 1/1`, поэтому пауза по
  умолчанию здесь 1 с, а `/internal/*` из `robots.txt` не обходится вовсе;
- сортировка по названию на сайте сломана: `/list?sortType=name` отдаёт первую
  страницу, а вторая уже пустая. Обход по ней невозможен, поэтому для полного
  каталога используются `popularity` (по умолчанию), `created`, `updated`,
  `rating`;
- **страницы глав (`chapter_pages`) есть не у всех глав.** Список картинок лежит
  в разметке ридера (`rm_h.readerInit`), но сайт отдаёт его не всегда: главы
  18+ и главы, которые ещё не опубликованы, гостю открываются как карточка
  тайтла — без вызова `readerInit` и без картинок. В этом случае метод честно
  возвращает пустой список; обойти это без учётной записи нельзя. Список глав
  при этом отдаётся полностью и всегда.

```bash
python main.py selfmanga search "берсерк"             # 1 запрос, ~1 с
python main.py selfmanga catalog --page 2
python main.py selfmanga dump --csv                   # 3410 тайтлов, 69 страниц
python main.py selfmanga enrich --limit 0 --csv       # + статусы, персоны, статистика
python main.py selfmanga chapters djodjo__vpered_legenda_
```

## Приложение (manga-gui)

Читатель манги поверх тех же парсеров: библиотека, поиск по всем площадкам,
карточка тайтла, два режима чтения и офлайн. Один и тот же код работает на
Android, iOS и десктопе — отличается только раскладка.

```bash
pip install flet

python main.py gui          # окно на десктопе
manga-gui                   # то же самое, отдельная команда
python main.py gui --web    # открыть в браузере (отладка вёрстки)
```

Сборка мобильных версий — стандартными средствами Flet:

```bash
flet build apk              # Android: .apk или .aab для Google Play
flet build appbundle        # Android: bundle для Play
flet build ipa              # iOS: только с macOS и Xcode
flet build macos / linux / windows
```

### Экраны

| Экран        | Что делает                                                          |
|--------------|---------------------------------------------------------------------|
| **Библиотека** | Избранное, история чтения и скачанные главы — всё из локальной БД  |
| **Обзор**    | Список источников и каталог выбранного с бесконечной пагинацией    |
| **Поиск**    | Запрос уходит на все площадки сразу, выдача приходит по мере ответов |
| **Карточка** | Обложка, рейтинг, авторы, жанры, описание, список глав со сортировкой |
| **Читалка**  | Вебтунс или постраничный режим, чтение скачанного без сети          |

На телефоне вкладки живут внизу (`NavigationBar`), на окне шире 720 px — в
сайдбаре (`NavigationRail`). Переключение происходит по ширине окна.

### Читалка

Два режима переключаются кнопкой в шапке, выбор запоминается:

- **Вебтунс** — вертикальный поток страниц, как на сайтах с вебтунами;
- **Страницы** — постраничный режим с RTL-листанием (свайп вправо — вперёд,
  вправо-вниз по краям экрана — листание), щипок масштабирует страницу.

Тап по краям листает, тап по центру прячет панели. Прогресс пишется в БД
на каждой странице и по выходе из экрана, поэтому книга открывается там же,
где её оставили; прочитанные главы помечаются галочкой в списке.

### Скачивание и офлайн

Кнопка у главы качает её целиком в фоне (можно все главы разом), список
«Скачанное» в библиотеке показывает, что лежит на диске. Отдельная кнопка
в шапке читалки докачивает текущую главу.

Картинки идут через дисковый кэш, а не напрямую по сети. Это не оптимизация,
а необходимость: CDN площадок отдают изображения только с `Referer` сайта —
без него ReManga отвечает `403`, и Flet этот заголовок подставить не может.
Побочный эффект полезный: повторное открытие главы мгновенное, а прочитанное
читается без интернета.

Кэш и база лежат в каталоге приложения:

| Платформа | Путь                                                    |
|-----------|---------------------------------------------------------|
| Windows   | `%LOCALAPPDATA%\manga-parser`                            |
| macOS     | `~/Library/Application Support/manga-parser`             |
| Linux     | `~/.local/share/manga-parser`                            |
| Android/iOS | `<документы приложения>/manga-parser`                   |

Внутри: `library.sqlite3` (избранное, история, прогресс), `covers/` (обложки),
`pages/` (кэш прочитанного), `chapters/` (явные скачивания).

### Ограничения источников в приложении

Приложение не может показать больше, чем отдаёт сайт, поэтому ограничения
показаны заранее — на плитке источника и в списке глав:

| Источник      | Ограничение                                       |
|---------------|---------------------------------------------------|
| **Com-X**     | только каталог: сайт закрыт антиботом            |
| **Desu.Me**   | доступна первая глава тома                        |
| **SelfManga** | главы 18+ открыты гостю без картинок             |
| **InkStory**  | список глав обрезан первой страницей              |
| **MangaLIB**  | карточка без описания и жанров (их нет в API)    |

### Проверка без окна и сети

```bash
python tools/gui_smoke.py        # все маршруты строятся без исключений
python tools/gui_interactions.py # 53 проверки: каждая кнопка и каждый тап
python tools/gui_e2e.py          # каталог -> карточка -> главы -> читалка
python tools/gui_offline.py      # скачивание главы и чтение без сети
python tools/gui_shots.py        # скриншоты экранов в shots/
```

`gui_interactions.py` жмёт кнопки так же, как это делает Flet, и проверяет
не «было ли исключение», а изменилось ли что-то снаружи: маршрут, состояние
БД, дерево контролов. Кнопка, которая ничего не меняет, попадает в отчёт как
неработающая — именно так были найдены поломки вкладок библиотеки и кнопки
«назад» в читалке.

## Архитектура

Зависимости идут строго сверху вниз, обратных импортов нет.

```
main.py                       единственная точка входа
src/mangaparser/
├── cli/                      argparse, маршрутизация, подсказки
├── application/              сценарии: поиск, обход, enrich, index, merge
├── sources/                  конкретные сайты
│   ├── registry.py           реестр источников (единственное место перечисления)
│   ├── mangalib/             client.py + модель Manga
│   ├── remanga/              client.py + модель Title
│   ├── inkstory/             client.py + модель Book + parsing.py (разбор HTML)
│   ├── buzumanga/            client.py + модель Manga + slug.py (транслитерация)
│   ├── comx/                 client.py + модель Title + parsing.py (sitemap)
│   ├── desu/                  client.py + модель Title + parsing.py (sitemap + карточка)
│   └── selfmanga/             client.py + модель Manga + parsing.py (SSR-разметка)
├── infrastructure/
│   └── storage/              exporters.py, checkpoint.py, sqlite_index.py
├── gui/                     графическое приложение (Flet): Android / iOS / десктоп
│   ├── app.py                навигация, маршруты, адаптивная раскладка
│   ├── state.py              состояние окна: источники, закачки, настройки
│   ├── store.py              локальная БД: избранное, история, прогресс, загрузки
│   ├── images.py             кэш обложек и страниц, скачивание глав
│   ├── hub.py                доступ к источникам, чтение полей, поиск по всем
│   ├── paths.py              каталоги приложения по платформам
│   ├── theme.py              AMOLED-тема Material 3 и палитра
│   ├── widgets.py            обложки, карточки, чипы, состояния, уведомления
│   └── views/                экраны: library, explore, sources, search, details, reader
└── core/                     контракты и утилиты, внешних зависимостей нет
    ├── ports.py              протоколы Source / Checkpoint / OfflineIndex
    ├── models.py             Item, Chapter, chapter_field, extract_pages
    ├── http.py               сессия с ретраями, Http, Throttle
    └── text.py               strip_tags, to_float, to_int, to_compact_int, label, dedupe
tests/                        200 тестов без обращения к сети
tools/                        проверки GUI: маршруты, сквозной путь, скриншоты
data/                         выгрузки (git-ignored)
shots/                        скриншоты экранов (git-ignored)
```

Правила, которые держат архитектуру чистой:

- **core** не знает ни про один сайт и не импортирует `requests`-логику выше себя.
- **application** работает только через порты `core.ports.Source`; названий
  сайтов в нём нет вообще.
- **sources** могут зависеть от `core`, но не друг от друга и не от
  `application`/`cli`.
- **cli** только собирает аргументы и вызывает сценарии; бизнес-логики в нём нет.
- **gui** — ещё один клиент тех же источников: ходит в них через
  `sources.registry`, ничего не зная про `application` и `cli`. Поэтому
  приложение и парсеры не связаны: новая команда CLI не ломает окно, а
  новый экран не требует правок парсеров.

Правила, которые держат графику работоспособной (проверены на Flet 1.0):

- **сеть только в потоках Flet.** Синхронный `requests` нельзя вызывать из
  обработчика события: `page.run_thread(...)` — единственный способ, при
  котором обновления доходят до клиента. Свой `threading.Thread` для
  отрисовки не годится: страницы и обложки вставятся, но не показываются.
- **список пересобирается целиком.** Если у элемента `ListView`/`GridView`
  изменилось только содержимое контейнера, Flet не перестраивает элемент —
  нужно переприсвоить `controls`.
- **у `ft.Text` нельзя задавать `height` вместе с `max_lines`** — такой текст
  не рисуется вообще.
- **полупрозрачные фоны не пишутся строкой `rgba(...)`** — внутри `Stack`
  Flet 1.0 молча не рисует их: обложки и панели читалки остаются без фона,
  белые иконки теряются на белой манге. Прозрачность задаётся через
  `Colors.with_opacity` (см. `theme.veil`).
- **переход по странице webtoon считается по offset, а не через
  `scroll_to(scroll_key=...)`** — прокрутка по ключу в Flet 1.0 тихо не
  работает (списки строятся динамически). Высоты страниц считаются по
  пропорциям картинок и подгоняются по событиям прокрутки
  (`ReaderView._calibrate`).
- **слои в `Stack` привязываются** (`left/top/right/bottom`): без привязки
  стеночный контейнер может растянуться на весь стек и перекрыть
  содержимое.
- **картинки идут через диск**, потому что CDN источников требуют `Referer`
  (см. раздел про кэш).

### Как добавить источник

1. Создать `src/mangaparser/sources/<name>/client.py` с классом клиента:

```python
from ...core.http import Http, Throttle, build_session
from ...core.models import Item

class MyClient:
    name = "mysite"
    item_class = MyBook        # dataclass, наследующий Item
    dedupe_key = "id"          # поле дедупликации в выгрузке
    key_hint = "slug"          # что нужно для details()/chapters()
    enrichable = True          # False, если details() не даёт больше каталога

    def catalog(self, page: int = 1, **kw) -> list[MyBook]: ...
    def search(self, query: str, page: int = 1, **kw) -> list[MyBook]: ...
    def details(self, key: str, **kw) -> MyBook: ...   # карточка: описание, жанры, авторы
    def chapters(self, key: str, **kw) -> list[dict]: ...
    def chapter_pages(self, key: str, chapter: dict, **kw) -> list[str]: ...
    def iter_catalog(self, *, delay, max_pages=None, checkpoint=None, on_page=None, **kw): ...
```

2. Добавить `build()` и `describe()` в модуль.
3. Вписать одну строку в `sources/registry.py`.

CLI, `application` и тесты при этом не меняются: команды уже есть.

## Выгрузки

`dump` создаёт три файла с одинаковыми данными:

- `<source>_catalog.json` — основной формат;
- `<source>_catalog.csv` — для Excel (UTF-8 BOM, колонки — объединение всех полей);
- `<source>_catalog.jsonl` — чекпоинт по ходу обхода, из него же строится
  офлайн-индекс.

Во всех записях есть колонка `source`, а `title` приведено к общему виду —
поэтому каталоги разных сайтов можно склеивать в один датасет.

## Тесты

```bash
pip install pytest
python -m pytest tests -q     # сеть не используется: ответы API — фикстуры
python -m ruff check .
```

Тесты CLI и парсеров сеть не трогают. Проверки графики живут отдельно, в
`tools/`, и запускаются вручную: часть из них ходит на сайты и открывает
настоящее окно (список — в разделе про приложение).

## Зависимости

Python >= 3.11, `requests`, `urllib3`. Больше ничего: парсинг HTML сделан
на регулярных выражениях и JSON-LD, поэтому нет тяжёлых зависимостей.

Графическому приложению дополнительно нужен `flet` (>= 1.0). Парсерам он не
нужен: `pip install -r requirements.txt` ставит и его, но CLI работает и без
него — `python main.py gui` в этом случае подскажет, что не хватает пакета.
